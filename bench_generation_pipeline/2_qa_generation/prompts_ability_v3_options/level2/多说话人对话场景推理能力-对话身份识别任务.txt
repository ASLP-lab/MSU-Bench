# 多说话人对话场景推理能力：对话身份关系推理（2人关系识别｜选择题｜统一输出格式｜含 speaker_index）
你是 QA 构造专家。输入为多说话人对话转录与音频（含 spk_id、transcript，可能含 start_time/end_time/seg_id，且你可以听音频）。
目标：构造客观单选题评估模型的【两位说话人在整段对话中的身份关系】（如：医生-患者、老师-学生、采访者-受访者、同事、朋友、夫妻、顾客-服务员等）。

仅生成以下 question_type（不生成任何 retrieval 类题）：
- no_index / time_index / transcript_index / speaker_index / complex_index

================================================
【重要总原则】
- 只能依据对话中可观察证据判断关系（称呼、流程、权力关系、话题术语、交互模式等），严禁脱离语境主观编造。
- 禁止使用 turn/轮次/turn_index/第几轮定位。
- 题干只用于索引到“两位说话人”，按模板允许出现：时间范围与/或转录片段与/或全局顺序（speaker_index）。
- 选项中只写“关系名称”（可带极短括注，但不得出现证据句、不得出现时间）。
- 正确答案不能是 unknown；若只能选 unknown => 输出 []。
- 必须保证唯一正确：若同事vs朋友、老板vs客户等常见混淆无法排除 => 不出题，输出 []。

================================================
【spk_index 定义（必须严格遵守）】
- spk_index 是“全局说话人顺序编号”，基于整段输入转录中 spk_id 的首次出现顺序确定：
  - 第一个首次出现的 spk_id => spk_1
  - 第二个首次出现的 spk_id => spk_2
  - 以此类推
- spk_index 仅允许出现在：
  - speaker_meta 字段记录
  - question_type="speaker_index" 的题干
除 speaker_index 题干外，题干/选项/答案/解析不得出现 spk_id/spk_index。

================================================
【speaker_meta 选段与聚合规则（先选一次，全题复用｜强制执行）】
你必须先挑选“互动最密切、关系线索最清晰”的两位说话人，并输出 speaker_meta：
- spk_a：说话人A（同一 spk_id，可放多个 seg，但 spk_a[0] 是题干索引锚点）
- spk_b：说话人B（同一 spk_id，可放多个 seg，但 spk_b[0] 是题干索引锚点）

强制要求：
1) speaker_meta.spk_a 内所有 seg 的 spk_id 必须相同；
2) speaker_meta.spk_b 内所有 seg 的 spk_id 必须相同；
3) spk_a 的 spk_id 与 spk_b 的 spk_id 必须不同；
4) spk_a[0] 与 spk_b[0] 必须都能唯一定位到输入（优先 seg_id；其次 start/end；再其次 transcript 唯一片段）；
5) 两人都至少有 2 句“有信息量”的发言（不全是“嗯啊好对”等），且至少存在 2 类可核验关系线索；
6) spk_a[0] 与 spk_b[0] 都不能是整段音频的第一句话（避免热身寒暄导致难判）。

================================================
【最终输出格式（严格 JSON｜speaker_meta 单独输出一次）】
输出为一个 JSON 数组：
- 第 1 个元素：只包含 speaker_meta
- 后续元素：每个元素是一道选择题对象
若所有模板都无法保证唯一正确 => 输出 []（不要只输出 speaker_meta）。

[
  {
    "speaker_meta":{
      "spk_a": [{"seg_id":"...", "start_time":xxx, "end_time":xxx, "transcript":"...", "spk_id":"...", "spk_index":"spk_1",
                 "age":"...|unknown|null", "gender":"...|unknown|null", "emotion":"...|unknown|null", "accent":"...|unknown|null"}],
      "spk_b": [{"seg_id":"...", "start_time":xxx, "end_time":xxx, "transcript":"...", "spk_id":"...", "spk_index":"spk_2",
                 "age":"...|unknown|null", "gender":"...|unknown|null", "emotion":"...|unknown|null", "accent":"...|unknown|null"}]
    }
  },
  {
    "question": "...",
    "question_type": "no_index|time_index|transcript_index|speaker_index|complex_index",
    "options": ["A. ...","B. ...","C. ...","D. ..."],
    "answer": "A",
    "answer_text": "...",
    "rationale": ["A. ground truth","B. wrong speaker","C. hallucination","D. unknown"]
  }
]

字段硬约束：
- no_index：评测侧会提供两段切分音频：音频1=spk_a[0]，音频2=spk_b[0]；题干不得出现时间与 transcript。
- time_index/complex_index：
  - 第一段时间范围必须取自 spk_a[0].start_time/end_time；
  - 第二段时间范围必须取自 spk_b[0].start_time/end_time；
  不得自行编造时间。
- transcript_index/complex_index：
  - content_a 必须来自 spk_a[0].transcript（逐字，可截取连续子串且需唯一定位）；
  - content_b 必须来自 spk_b[0].transcript（同上）。
- options 必须为 4 个且顺序打乱；answer 指向唯一正确；answer_text 不含字母前缀。
- rationale 与 A-D 一一对应，且含义固定：
  - ground truth：正确关系
  - wrong speaker：对话中确实出现过、但属于“另一对说话人”的关系（或属于另一对人际关系线索），不属于本题两人
  - hallucination：对话中完全没出现过的关系（看起来合理但无证据）
  - unknown：固定 “无法判断（证据不足）”
注意：若你无法在对话中找到“另一对说话人确实出现过的关系”来做 wrong speaker，则本题不生成，输出 []（不要退化成随便写一个错项）。
================================================
【高置信度身份/关系优先级（强制）】
本任务的“关系”不仅可以是泛化角色对（如审讯者-被审讯者），更应优先输出对话中可高置信推断的【社会身份关系】。
当对话证据足够明确时，正确答案必须向“社会身份/人群属性”靠拢，而不是给出模糊的“审讯人/被审讯人”。

你必须按以下优先级选择 ground truth（从高到低）：
1) 具体现实身份（高置信）：
   - 例如“警务人员-社会民众”“警务人员-案件嫌疑人”“警务人员-复员老兵（退伍军人）”
   - 若对话提到“复员/退伍/转业/军龄/部队”等明确线索，且对象指向其中一位说话人，则应优先输出“警务人员-复员老兵”，而不是“审讯者-被审讯者”。
2) 场景角色但仍具体：
   - 例如“警务人员-案件相关人（证人/报案人/当事人）”
3) 仅在证据不足以细分时，才允许用泛化关系：
   - “审问者-被问询者/被盘问者”

若无法达到 (1)/(2) 的高置信标准，则本题不生成（输出 []），不要用模糊关系凑题。

================================================
【证据门槛（必须满足才允许细分身份）】
- “警务人员”必须有强线索：制服/警官称呼/执法流程用语/询问案情/立案/笔录/证据/编号等。
- “嫌疑人/民众/老兵”等必须有直接或强指向线索：
  - 嫌疑人：涉及是否作案、动机、时间线、对质、辩解、证据指控等强指向
  - 社会民众/当事人/证人/报案人：描述见闻、提供线索、报案经过、协助调查等强指向
  - 复员老兵：明确出现“复员/退伍/转业/老兵/部队经历”等，并可归属到其中一位说话人
若这些线索只是一句模糊提及且无法唯一归属 => 不细分，输出 []。

================================================
【高难度错误选项（near-miss）构造规则：同执法流程、身份细节错】
在构造 options 时，必须包含一个“高难错项”：
- 保持“执法问询/盘问流程”不变，只把被问询者的社会身份换成近邻类别，使其非常合理但与证据冲突。
例如对话证据支持“警务人员在问询复员老兵”：
- ground truth（正确）：警务人员—复员老兵（退伍军人）
- high-hard wrong（高难错）：警务人员—案件嫌疑人（或 警务人员—普通社会民众）
反过来亦然：如果真实是“嫌疑人”，高难错可改成“社会民众/证人/复员老兵”。

================================================
【选项写法约束（避免模糊）】
- 选项必须写成“身份A—身份B”形式，身份B必须体现社会身份细分（民众/嫌疑人/复员老兵/证人/报案人等）。
- 禁止把 ground truth 写成“审讯者—被审讯者”这类泛化词，除非证据确实不足以细分且你仍能唯一判定（通常不允许出题）。
================================================
【关系候选空间（动态生成）】
- 不固定关系类型；必须基于对话内容动态选择。
- ground truth 必须唯一合理，并能排除至少 1 个常见近邻关系（如同事vs朋友、顾客vs咨询者等）。
- 选项 A/B/C（非 unknown）长度尽量接近，仅写关系名称（允许极短括注，但不超过 8 个字，不得出现证据句）。

================================================
【通用选项构造规则（所有模板适用｜4选1）】
每题 4 个选项必须包含（顺序打乱）：
A) ground truth：两人真实关系（唯一合理）
- B. wrong speaker：对话中另外两个说话人的关系套用到当前说话人关系上，如警局同事
- C. hallucination（高难近邻错）：同一对说话人，但身份细分错（同流程，社会身份错）
- D. unknown：无法判断（证据不足）
若任一类无法保证，直接输出 []。

================================================
【模板集合（每模板最多 1 题，满足则生成，不满足跳过）】

模板1｜no_index（两段切分音频索引，不给时间与文本）
question_type = "no_index"
题干：
“下面音频中的两个说话人，从整段对话来看，他们之间的关系是什么？请选择最符合的一项。”
说明：
- 音频1对应 spk_a[0]；音频2对应 spk_b[0]
- 题干不得出现时间与 transcript。

模板2｜time_index（双时间范围索引）
question_type = "time_index"
题干（按你要求）：
“音频中第 S1 秒到第 E1 秒讲话的说话人以及在第 S2 秒到第 E2 秒讲话的说话人在整段对话中的关系是什么？请选择最符合的一项。”
约束：
- [S1,E1]=spk_a[0].start_time/end_time
- [S2,E2]=spk_b[0].start_time/end_time
- 题干不出现 transcript。

模板3｜transcript_index（双文本索引）
question_type = "transcript_index"
题干（按你要求）：
“音频中说过‘content_a’的说话人以及说过‘content_b’的说话人在整段对话中的关系是什么？请选择最符合的一项。”
约束：
- content_a 来自 spk_a[0].transcript（逐字且唯一定位）
- content_b 来自 spk_b[0].transcript（逐字且唯一定位）
- 题干不出现时间。

模板4｜speaker_index（全局顺序索引：第1与第2）
question_type = "speaker_index"
题干（按你要求）：
“整段对话第一个发言的说话人以及第二个发言的说话人在整段对话中的关系是什么？请选择最符合的一项。”
生成条件（必须全部满足）：
- 本题要求两人分别为 spk_1 与 spk_2；
- 即 spk_a[0].spk_index=spk_1 且 spk_b[0].spk_index=spk_2（或反之，你需要按题干顺序固定 A=spk_1，B=spk_2）；
- 若你选择的最密切互动对不是 spk_1/spk_2，则跳过该模板（不要为了出题强行换人导致关系线索不清晰）。
题干不出现时间与 transcript。

模板5｜complex_index（双时间+双文本索引）
question_type = "complex_index"
题干（按你要求）：
“音频中第 S1 秒到第 E1 秒说过‘content_a’的说话人与第 S2 秒到第 E2 秒说过‘content_b’的说话人在整段对话中的关系是什么？请选择最符合的一项。”
约束：
- S1/E1/content_a 同时来自 spk_a[0] 的同一 seg
- S2/E2/content_b 同时来自 spk_b[0] 的同一 seg

================================================
【反泄露选段约束（强制执行｜避免题干从文本直接点名身份）】
你在选择 spk_a[0] 与 spk_b[0] 作为题干索引锚点（time_index / transcript_index / complex_index 会暴露 transcript）时，必须尽量避免选到“直接点名双方身份/关系”的句子，否则会在题干里给模型文本提示，破坏评测。

1) 禁止作为锚点的“直指身份词/关系词/职业称谓”示例（包含但不限于）：
- 亲属/关系：爸/妈/父亲/母亲/儿子/女儿/老公/老婆/媳妇/丈夫/妻子/哥哥/姐姐/弟弟/妹妹/爷爷/奶奶/外公/外婆/叔叔/阿姨/舅舅/姑姑/侄子/表哥/同学/同事/室友/朋友/兄弟/姐妹/闺蜜
- 职业/场景角色：医生/护士/病人/患者/老师/学生/教授/老板/经理/领导/下属/员工/同事/客户/顾客/店员/服务员/客服/房东/租客/警察/律师/法官/记者/主持人/采访者/受访者/教练/学员/师傅/徒弟
- 明确关系指称：夫妻/父子/母子/师生/医患/上下级/雇佣/租赁/采访/咨询 等
- 明确“呼叫式点名”：如“X老师/医生/老板/房东/警官/经理/师傅/同学”等（含“老师/老板/房东”等后缀）
注意：只要该片段 transcript 中出现上述强指示词，就视为“身份泄露风险高”。

2) 对 transcript_index / complex_index：
- anchor content 必须来自“低身份泄露风险”的句子：不包含上述词汇与直接称谓；
- 若无法找到满足条件的片段，则跳过 transcript_index 与 complex_index（可只出 no_index / time_index / speaker_index）。


3) 若你无法同时满足：
- (a) 关系可唯一确定（线索≥2类），以及
- (b) 锚点片段不含直指身份词，
则优先保证评测不泄露：宁可输出 [] 或只生成不泄露的题型（no_index/time_index/speaker_index），不要用“点名身份”的句子做 transcript_index/complex_index。

================================================
【全局失败条件（任一触发直接输出 []）】
- 无法选出两位说话人满足：互动紧密、线索≥2类、关系可唯一确定
- 无法构造 wrong speaker（对话中确实出现过但属于另一对人的关系）
- hallucination 无法保证“对话中未出现过”
- 任一模板无法保证唯一正确

开始生成：请仅输出符合格式的 JSON；若无法保证唯一正确则输出 []。
